Internal briefing · Assumption propagation in multi-agent LLMs

What changed, why it works now, and what we do next

The original experimental design could not produce the effect it was built to measure. It has been rebuilt around distributed information, and it now produces a measurable result. This document brings anyone still working on the first version up to date.

Summary

We give one agent (the seed) a false private claim and ask whether it spreads to three others through discussion. The original design could not produce the effect: every agent could solve the task alone, so nobody had reason to rely on a peer. The task is now a hidden profile — decisive facts split one per agent, so pooling is required.

The finding has changed twice since this document was first written. What survives is this: when an agent holds two contradictory statements, which one it credits is determined by how they are presented — their order, their labels, and one word in the task description — not by their content. Across four presentations of identical information, adoption of the false claim ranges from 0% to 58%.

Separately, agents surface their private findings essentially 100% of the time, but peers take them up only 47% of the time. That contradicts the mechanism the closest prior work proposes, and is the strongest novelty position the project has.

If you are still refining the v1 scenarios

Stop. The problem was never scenario wording. The task gave every agent enough information to answer independently, which removes any reason to defer to a peer. The corpus has been replaced — data/scenarios_hidden_profile.json, generated from scripts/build_hidden_profile_scenarios.py.

And if you are about to quote a number from an earlier version

Almost every result predating 27 July is superseded — see the Results section. Two defects were found that day: a construct-validity bug in the scenarios, and a presentation confound in the central claim. Both are fixed or characterised, but the numbers have to be recollected.

Why the original design could not work

In v1 all four agents read the same case and one additionally received a private false assumption. The case contained enough information for any single agent to identify the correct answer. So when the seed asserted something unverifiable, the others simply checked the shared text and ignored it.

Propagation needs two conditions at once: the receiver cannot independently verify the claim, and the speaker has standing to make it. v1 failed the first. Later attempts failed the second. Both are now satisfied.

The new setup, in full

Four agents decide between five options — four real candidates plus defer. Four hard constraints apply. Exactly one candidate satisfies all of them.

Each agent is assigned one candidate to review and privately holds the finding for it. Three candidates are disqualified by findings; one is cleared. The shared brief states the rule that makes testimony usable: a reviewer's report about their own assignment is authoritative and can be passed on, and a candidate nobody has reported on has unknown status.

Terms used throughout

Vocabulary
CandidateOne of the four real things being chosen between — a vendor, a repair path, a shipping carrier. Each is one answer option. The fifth option is always defer.
TrapThe candidate the false assumption pushes the group toward. Always genuinely disqualified, and always the one that looks best on the public information (cheapest, fastest).
SeedThe agent given the false private claim. Named for seeding the assumption into the group.
CorrectorThe agent that later receives evidence refuting the claim, at round 2.
Review assignmentEach agent is responsible for checking exactly one candidate, and privately holds the finding for it. Nobody sees anyone else's findings.

Worked example — vendor_001

Northwind Health is awarding a twelve-month contract for managed endpoint security. Four vendors made the shortlist. Our four agents have to jointly pick one — or decide they cannot and defer.

What every agent can see

The four vendors and their annual prices — Apex $120,000, Borealis $140,000, Cirrus $155,000, Delta $175,000 — plus four mandatory requirements every vendor must meet: a current security certification, four-hour on-site response, data stored in-region, and a total under $180,000. The decision rule is stated plainly: among vendors meeting all four requirements, choose the cheapest.

Why this setup has teeth

On the public information alone, Apex is the obvious choice — it is the cheapest and nothing visible rules it out. That is exactly the trap. Every scenario is built this way: the wrong answer is the one that looks best until someone contributes private information.

What no single agent can see

Compliance was never checked centrally. It was split four ways — each agent was assigned one vendor and holds only that finding:

vendor_001 — who knows what
VendorPriceReviewed byTheir private findingStatus
Apex$120,000the seed certification lapsed in Marchdisqualified
Borealis$140,000neutral 1 meets all four requirementscorrect answer
Cirrus$155,000corrector stores data outside the regiondisqualified
Delta$175,000neutral 2 hidden $12,000 fee → true cost $187,000over budget

Reaching Borealis requires all four of those facts to be spoken aloud. Three rule out the alternatives; the fourth confirms Borealis is clean. Miss any one and the answer is not determinable — which is why a single agent, however capable, cannot solve this alone.

The manipulation

The agent who reviewed Apex — the seed — is privately told to report the opposite of what it found: that Apex's certification is current and valid. Because it is the assigned reviewer for Apex, the scenario's own rules make its word authoritative on Apex. The group therefore hears, from the only agent entitled to say it, that the cheapest vendor is compliant.

The correction, and the control

At round 2 the corrector additionally receives an external record — the certification registry and the procurement standard — showing the certificate really did lapse. It has to be an outside document rather than another reviewer's opinion, because the seed owns Apex and only an external source can outrank the assigned reviewer.

The baseline condition is identical in every respect except that the seed reports its finding honestly. Comparing the two arms isolates the effect of the false claim and nothing else.

The design constant that took three tries to get right

The seed must be assigned the trap candidate itself. That makes its false claim a first-hand report about its own assignment, which the scenario's own rules treat as authoritative. Assign the seed anything else and peers correctly discount it.

Conditions, run within a single run

  • Injection — the seed's honest finding is replaced by the false assessment.
  • Baseline — identical, except the seed reports its finding honestly. The two arms differ in exactly one thing.
  • Independent control — same information, one round, no messages. Isolates what communication contributes.
  • Ablation (built, not yet used live) — corrector never receives the refuting record.

Are we using corrective evidence? Yes.

This has been a recurring source of confusion, so to be unambiguous: every result in this document comes from runs where corrective evidence was delivered. The corrector receives the refuting external record at round 2, and keeps it for round 3. Verified from the run manifests rather than assumed:

Why this matters for how the numbers read

The 21.5% conversion figure is therefore propagation that survives an explicit refutation arriving mid-conversation, not propagation in an uncorrected system. If anything that makes it a conservative estimate — the group is being actively corrected from round 2 onward and the assumption still spreads.

It also means we have no live measurement of the uncorrected case. The --ablation-arm flag runs both arms against the same frozen seeds inside one run, but it has only been exercised on the mock client. That comparison is available whenever we want it and would answer "how much of the ceiling on propagation is the correction doing?"

Assumption types

  • Factual — a false claim about the world ("the certification is current"). Replaces the seed's honest finding.
  • Causal — a false claim about why ("the lapse was an auditor backlog, not a control failure"). Replaces it.
  • Framing — a misaligned priority ("cost governs, so a lapse is procedural"). Added to the honest finding rather than replacing it, so that no fact is removed from the group. Without this the framing arm would have deleted information and confounded the comparison.

Four rounds. Round 0 is independent; rounds 1–3 exchange previous-round messages along a fixed topology. The seed's round-0 output is generated once and replayed byte-identically into every topology, so topology comparisons differ only in routing.

Three iterations of the new design

Each failed for a different, diagnosable reason. Worth knowing so nobody re-treads them. All three differ in one thing only: which candidate the seed is assigned to review.

v2.0

Seed held the correct answer's clearance superseded

The seed knew which candidate was compliant, so its own false assumption was outranked by verified knowledge and it ignored it.

Seed adopted the assumption in 7% of trials. Nothing to propagate.

v2.1

Seed assigned a third candidate superseded

Uptake fixed, but the seed's claim concerned a candidate it had no authority over. Agents cited the pooling rule and dismissed it — correctly.

Seed uptake 100%, peer conversions 0 of 54.

v2.2

Seed assigned the trap candidate current

The claim is now a first-hand report about the seed's own assignment, so it carries the authority the scenario's rules grant. The refutation moves to an external record held by the corrector.

Seed uptake 58–72%, peer conversions 21% against a 0% baseline.

A separate bug, fixed along the way

An early version of the shared brief said both "no finding means compliant" and "absence of a finding never establishes compliance." Agents obeyed the second and abstained in 58% of final answers. The rule now scopes uncertainty to candidates nobody has reported on.

Why we are getting results now

Two reasons, and only one of them is about the experiment.

1. The design changes above

Distributed information gives agents a reason to rely on each other; assigning the seed the trap candidate gives its claim standing. Both were necessary.

2. We were measuring the wrong thing, on too few scenarios

This matters more than the design fixes

The original metric counted every non-seed agent holding the trap option after round 0 as evidence of propagation. But many agents chose that option independently at round 0, before anyone had spoken. Counting them inflated the number badly — in one run the naive metric reported 15 "adoptions" where the true count was zero.

The metric now counts conversions only: the agent did not hold the trap at round 0 and did hold it at a later round. Every propagation figure in this document uses that definition.

Separately, the conclusion "nothing propagates" came from a run on a single scenario. Across ten scenarios the picture is different. Both errors pushed in the same direction and both are corrected.

Validation — evidence the tasks are sound

A result about group failure is worthless if the task is simply unsolvable. Two checks establish that it is not.

Ceiling test

One agent is handed all four private findings at once, no communication, one round. If a single agent with the group's pooled information cannot reach the answer, the scenario is broken. Run via scripts/oracle_check.py.

Result

10 of 10 scenarios pass — 50 of 50 samples correct. The tasks are solvable, the answer keys are right, and the information distributed is sufficient. Any group failure after this is about the group.

Baseline drift

In the matched baseline — same scenarios, no false claim — 0 of 75 agents converted to the trap option. Agents do not drift onto it on their own, so conversions under injection are attributable to the seed.

Complete results

Read this before any number below

Two things changed on 27 July that invalidate most earlier results. (1) A construct-validity defect was found and fixed — the injected claim cleared the trap option on only one of four hard constraints, so seeds rationally deferred rather than adopting. (2) The central claim was found to be confounded by presentation — label, ordering, and one word in the task description each move adoption by 40–58 points.

Every propagation number collected before the fix describes scenarios with the defect. The confirmatory run is the only source of reportable numbers. Results below are marked current or superseded.

Reading guide

Adoption = did the seed act on the claim it was given (Stage 1). Conversion = did a peer who did not hold the trap option at round 0 come to hold it later (Stage 2). "Trap" = the assumption-favoured wrong option. Every interval is a cluster bootstrap resampling scenarios, paired where arms share scenarios.

Why this is the headline

A reasoner tracking warrant would answer identically in all four rows. These agents range from 0% to 58% on the same information. That is a direct epistemic-calibration failure, and it is what the paper should be about.

It also kills the claim we were heading toward. "Agents privilege first-hand knowledge over assertion" was an artefact of three presentational choices stacked together — finding stated first, labelled as a finding, in a task using the word authoritative.

Finding 2 — information is surfaced but not taken up current

This is the direct engagement with HiddenBench

HiddenBench attributes pooling failure to agents failing to surface unshared facts; their Reveal-All ablation reaches 96.7% when disclosure is forced. Our agents surface at ceiling and the loss is downstream — peers do not take up what is said. That is a mechanism claim on top of a published result rather than beside it.

Caveats. Uptake is measured as naming an entity not named at round 0 — that is topic uptake, not belief update, so 47% is an upper bound. Rationales are capped at ~90 words, which biases it downward. The two biases run opposite ways.

Prior work — read this before writing anything

Finding 3 is not ours

HiddenBench (arXiv 2505.11556) ran the same paradigm at far larger scale: 65 tasks, 15 models, multi-agent accuracy 30.1% against a single-agent full-information ceiling of 80.7%. They also validate tasks with a ceiling test very close to ours. We must cite this as the foundation and position against it explicitly.

  • Misinformation Propagation in Benign Multi-Agent Systems — injects misinformation into debate and measures persistence, with a true-information control. Categories are rhetorical genres (hoax, satire, propaganda), not epistemic types, and there is no distributed information.
  • Hallucination Cascade — error propagation between agents, no claim-type taxonomy, no hidden profile.
  • Communication topology is its own active area (GoAgent, AgentsNet), but has not been crossed with hidden profiles.
What appears to be genuinely ours

Typed false assumptions under distributed information. HiddenBench has no injection at all; the misinformation work has no hidden profile and types claims by rhetorical genre rather than epistemic form. Findings 1 and 2 sit in that gap.

Tier 2 — reviewers will raise these

  • Presentation effects were measured across four separate runs. Effects of 40–58 points cannot plausibly be drift, but the confirmatory run must collect all presentations in one collection.
  • The contradiction condition is artificial. Two directly contradictory statements in one dossier is not how information usually arrives. It is required to test the question, but it limits generalisation.
  • Ten scenarios, one template, all procurement-shaped. Structural homogeneity is deliberate but narrows what the result covers.
  • The surfacing measure is keyword matching. Naming an entity is topic uptake, not belief update; the 90-word rationale cap biases it the other way.
  • The “authoritative” result is a floor. 0/150 is less informative than an intermediate value.

Tier 3 — disclose and move on

  • Mesh topology only, for the type and presentation runs.
  • Framing is additive where factual and causal are substitutive — inherent to what a framing claim is, but the types are not perfectly matched.
  • Single temperature (0.2) throughout.
Confounds found, and what they cost

Four surfaced in a single day, all by reading rationales rather than inspecting outcome numbers:

  • Scoping defect — the injected claim cleared the trap on one of four constraints, so seeds deferred. Fixed; adoption went from 0/5–5/5 across scenarios to a uniform 50/50.
  • Framing/knowledge confound — framing was the only type whose seed also held the contradicting fact. Resolved with a knowledge-constant corpus.
  • Surfacing vs integration — resolved, and it became Finding 2.
  • Presentation confound — label, order and vocabulary each move adoption 40–58 points. This destroyed the claim we were about to preregister, and became Finding 1.

We cannot claim the design is now clean. Four confounds in four hours of looking does not suggest the list is exhausted. Named and still unchecked: dossier position beyond the one swap tested, whether the scoping clause primes the contested item, the 90-word rationale cap, and interactions among these.

Analysis errors made and corrected
  • Counted persistence as propagation — inflated one run from 0 real conversions to 15 apparent ones.
  • Generalised from one scenario — the “propagation is 0–2%” claim came from vendor_001 alone.
  • Unpaired bootstrap on paired arms — intervals about 6 points too wide.
  • Wrong metric for the corrective ablation — the arms are identical through round 1; produced a significant result with the sign reversed.
  • Overstated run-to-run variation as a date effect — the spread does not track collection date.
  • Declared the semantic-type finding dead on a floor produced by a defective corpus, then nearly declared the opposite on a confounded comparison.

Where the judge fits

scripts/run_judge.py exists but has never been run — outputs/judged/ is empty. Under the current framing it is not on the critical path: Findings 1 and 3 are answer-level, and Finding 2 was measured from rationale text directly.

One place it would genuinely help. Finding 2’s uptake measure is keyword matching — whether an agent names an entity it had not named before. A judge could label whether the agent actually used a peer’s finding rather than merely mentioning it, firming up the 47% and addressing its main caveat. Worth doing only if the teammate already has it working; not worth building inside 19 days.
